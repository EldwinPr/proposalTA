\section{Rencana Implementasi}

Implementasi penelitian ini akan dilakukan melalui tahapan berikut:

\subsection{Penyiapan Infrastruktur}

\subsubsection{Perangkat Keras}
\begin{itemize}
    \item \textbf{SBC Platform:} Pengadaan Orange Pi 5 Pro beserta aksesoris pendukung (power supply, storage microSD/eMMC, cooling system)
    \item \textbf{VPS Platform:} Provisioning Oracle Cloud Free Tier (4 OCPU Ampere ARM, 24GB RAM) untuk evaluasi performa
    \item \textbf{Testing Infrastructure:} Laptop/PC untuk menjalankan aplikasi \textit{load testing} (untuk menghindari \textit{bottleneck} pada mesin penguji)
\end{itemize}

\subsubsection{Perangkat Lunak}
\begin{itemize}
    \item \textbf{Sistem Operasi:} Instalasi Linux (Armbian untuk Orange Pi, Ubuntu/Oracle Linux untuk VPS) pada kedua platform
    \item \textbf{Dependensi ERP:} Instalasi \textit{stack} perangkat lunak yang dibutuhkan ERPNext:
    \begin{itemize}
        \item Python 3.10+
        \item Node.js dan npm
        \item MariaDB/PostgreSQL
        \item Nginx (web server dan reverse proxy)
        \item Redis (caching dan session management)
        \item Supervisor (process management)
    \end{itemize}
    \item \textbf{Aplikasi ERP:} Instalasi Frappe Framework dan ERPNext dengan konfigurasi identik pada kedua platform
    \item \textbf{Dataset Demo:} Persiapan dataset demo yang konsisten untuk memastikan perbandingan yang adil
    \item \textbf{Aplikasi Pengujian:} Pengembangan aplikasi \textit{load testing} berbasis Go untuk simulasi beban kerja ERP (API calls, concurrent users, transaction patterns)
\end{itemize}

\subsection{Konfigurasi dan Validasi}

\begin{itemize}
    \item Konfigurasi jaringan dan keamanan dasar pada kedua platform (firewall, SSH access, SSL/TLS)
    \item Verifikasi instalasi ERPNext melalui akses web interface dan pengujian fungsional dasar
    \item Validasi kompatibilitas ERPNext pada arsitektur ARM (Orange Pi)
    \item \textit{Baseline benchmarking} untuk karakterisasi perbedaan intrinsik platform (CPU performance, I/O throughput, network latency)
\end{itemize}

\section{Rencana Evaluasi}

\subsection{Metode Pengujian}

Evaluasi akan dilakukan melalui dua tahap pengujian utama:

\subsubsection{Pengujian Kelayakan Fungsional}

\textbf{Tujuan:} Memastikan platform SBC mampu menjalankan fungsionalitas inti ERP dengan performa yang dapat diterima.

\textbf{Skenario Pengujian:}
\begin{itemize}
    \item Simulasi alur kerja bisnis umum: pembuatan \textit{sales order}, validasi faktur (operasi tulis), penarikan laporan, pencarian data produk (operasi baca) \cite{maddodi2018generating}
    \item Pengujian dilakukan dengan beban kerja normal (5-10 \textit{concurrent users}) untuk periode waktu tertentu (misal: 1 minggu) guna mengevaluasi stabilitas jangka panjang
\end{itemize}

\textbf{Metode Eksekusi:}
\begin{itemize}
    \item Konfigurasi A: ERP di SBC, aplikasi \textit{testing} di VPS (simulasi akses jarak jauh)
    \item Konfigurasi B: ERP di VPS, aplikasi \textit{testing} di SBC (untuk perbandingan)
    \item Pencatatan metrik: \textit{response time}, \textit{error rate}, \textit{resource utilization}
\end{itemize}

\subsubsection{Pengujian Batasan Kinerja (\textit{Stress Test})}

\textbf{Tujuan:} Mengidentifikasi titik batas (\textit{breaking point}) platform SBC dalam menangani beban kerja ERP.

\textbf{Skenario Pengujian:}
\begin{itemize}
    \item Simulasi lalu lintas tinggi dengan peningkatan bertahap jumlah \textit{concurrent users} (10, 25, 50, 100 users)
    \item Peningkatan frekuensi pemanggilan API hingga sistem menunjukkan degradasi performa signifikan atau mulai menghasilkan error
\end{itemize}

\textbf{Metode Eksekusi:}
\begin{itemize}
    \item Aplikasi \textit{load testing} Go dijalankan dari laptop terdedikasi untuk menghindari \textit{bottleneck} pada mesin penguji
    \item Pengujian diarahkan secara terpisah ke SBC dan VPS untuk mendapatkan data performa puncak masing-masing platform
\end{itemize}

\subsection{Alat dan Metrik Evaluasi}

\textbf{Alat Pengujian:}
\begin{itemize}
    \item Aplikasi \textit{load testing} berbasis Go (untuk konkurensi tinggi dan kontrol granular atas beban kerja)
    \item Utilitas monitoring Linux: \texttt{vmstat}, \texttt{iostat}, \texttt{htop} untuk monitoring resource utilization
\end{itemize}

\textbf{Metrik Kinerja:}
\begin{itemize}
    \item \textbf{Application Metrics:} Response time (ms), throughput (requests/second), error rate (\%)
    \item \textbf{System Metrics:} CPU utilization (\%), RAM usage (MB/\%), disk I/O (MB/s), network latency (ms)
\end{itemize}

\subsection{Rencana Analisis Data}

\begin{itemize}
    \item \textbf{Analisis Performa:} Pembuatan grafik perbandingan (throughput vs. concurrent users, response time distribution) untuk visualisasi perbedaan performa antar platform
    \item \textbf{Identifikasi Bottleneck:} Analisis korelasi antara resource utilization dan degradasi performa untuk mengidentifikasi komponen yang menjadi bottleneck (CPU, RAM, I/O)
    \item \textbf{Perhitungan TCO:} Perhitungan Total Cost of Ownership untuk periode 3 dan 5 tahun dengan komponen:
    \begin{itemize}
        \item SBC: CAPEX (hardware) + OPEX (listrik)
        \item VPS Komersial: OPEX (biaya sewa bulanan dari Hostinger/Biznet/DigitalOcean)
    \end{itemize}
    \item \textbf{Trade-off Analysis:} Analisis kualitatif trade-off antara kelayakan teknis (performa, kapasitas) dan finansial (TCO, break-even point)
\end{itemize}
